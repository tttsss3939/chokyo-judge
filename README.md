# 調教ジャッジ

JRA-VAN アプリの「調教タイム」画面のスクショを読み込み、追い切りを判定するスマホ向け Web アプリ。
GitHub Pages で動き、OCR はブラウザ内（Tesseract.js）で行うので画像は外部に送信しない。Claude のトークンも使わない。

## 使い方（iPhone）

1. Safari で `https://tttsss3939.github.io/chokyo-judge/` を開き、共有 →「ホーム画面に追加」
2. ホーム画面のアイコンから起動 → 馬を追加（右上の選択欄 →「＋ 馬を追加…」）
3. 「スクショを読み込む」で JRA-VAN の調教タイム画面のスクショを選ぶ（複数枚まとめて選べる。重なった行は自動で統合）
4. 確認・修正画面で、行ごとのスクショ画像と数字を見比べて直す → 保存
   - オレンジ枠 = 要確認（6F>5F>…>1F が崩れている、ラップが10〜30秒の外、下段ラップと合わない、日付の並びが変 など）
   - 「要確認のみ表示」で怪しい行だけに絞れる。画像はタップで拡大
5. 「出走レース」に日付・レース名・着順を登録。着順が空欄のレースが判定対象になる

> ホーム画面から起動したアプリと Safari のタブは保存領域が別です。どちらか一方で使い、
> データの変更から7日バックアップしていないと画面上部にお知らせが出ます。「バックアップ」で共有シートが開くので、
> 「ファイルに保存」（iCloud Drive など）や LINE・メールに送っておけば、機種変更や削除のときもメニューの「バックアップから復元」で戻せます。

OCR エンジンとモデル（約13MB、`vendor/tesseract/`）はアプリに同梱しており、初回起動時にまとめて端末にキャッシュされます。
以降は電波が無くても起動・スクショ読み取り・判定ができます（Service Worker、`sw.js`）。

## そのほかの機能

- **講評文**: 判定の根拠を「一言まとめ＋箇条書き」で表示（`js/comment.js`、点数には影響しない）。
  終い・全体・ラップ・1週前・乗り込み量に加え、自己ベスト更新、コース替わり、レース前4週の追い切り本数、前走・好走時（3着以内）の最終との比較も拾う
- **馬名の自動判定**: スクショ上部に馬名が写っていれば日本語OCRで読み取り、保存先の馬を自動で選ぶ（未登録なら新規作成）
- **出走馬の比較**: 同じ日付・同じレース名を登録した馬を、点数順に並べて表示（「スワンS(GII)」と「スワンS」は同じレースとみなす）
- **レース入力の補助**: 「＋ 追加」で、JRA重賞（今後／終了）と、他の馬で登録済みのレースをプルダウンから選べる。レース名は入力候補も出る
- **成績の検証**: メニュー →「成績の検証」。全馬の判定済みレースを S/A/B/C 別に件数・平均着順・勝率・連対率・3着内率で集計し、点数と着順の順位相関も表示。
  さらに加減点の要素（ラスト1F・全体時計・ラスト2F形状・1週前・乗り込み量）ごとに「加点/±0/減点のときの3着内率・平均着順」を出すので、配点の見直しに使える。着順は「4着」「4着(3人気)」などから数字を読む

## 判定ロジック

`training_judge.py` と `js/judge.js` は同じロジック（`tests/parity.mjs` で一致を検証）。

- 追い切り: 坂路 4F ≤ 58.0 秒、ウッド 5F ≤ 72.0 秒（それ以外はキャンター）
- 調整期間 = 前走の翌日〜レース前日
- 最終 = レース2〜6日前の追い切り（7日前の日曜追い・前日の調整は最終にしない。2〜6日前が無いときだけ前日）。
  同じ週に複数あれば、一番強い追い切り（1Fあたり基準時計より何秒速いか）から0.5秒以内のうち遅い日
- 1週前・2週前 = 最終追い切りの日（まだ無ければレース4日前）から7日前・14日前に最も近い追い切り（±3日）
- 基準 = その馬の過去レースの最終追い切り（同コース）の平均。対象レースより前のデータのみ（point-in-time）。過去レースが未登録なら、自身の普段の追い切り（同コース、レース22〜365日前）が3本以上あればラスト1Fの速い方の半分の平均。それも無ければ、他の登録馬の最終追い切り（同トレセン・同コース、対象レースより前）が3本以上あればその平均、さらに無ければ汎用基準（坂路 4F53.5/1F12.3、ウッド 5F67.0/1F11.6）
- 点数（50点スタート）
  - ラスト1F: 基準との差 0.1秒 = 3点（±12）
  - 全体時計: 基準との差 1秒 = 4点（±12）
  - ラスト2Fの形（1F − ラスト2F目）: ≤-0.1 加速 +5 / ≤0.3 維持 0 / ≤0.6 減速 -5 / それ以上 -10
  - 1週前: ラスト1F が基準+0.2以内 +5、13.0以上 -5。1週前なしは前走から21日以内なら 0、それ以外 -8
  - 乗り込み量: 直近14日の本数が過去平均の 0.7倍未満 -5、1.2倍超 +3
- ランク: 70以上 S / 60以上 A / 45以上 B / それ未満 C
- 最終追い切りがまだのレースは「最終追い切り待ち」として判定基準を表示

配点は 2026/10/12 に見直した（旧: ラスト1F 0.1秒=5点±15、全体 1秒=5点±10、形状 +8/0/-6/-12）。
ラスト1Fの0.1〜0.2秒差は馬場や計測のぶれでも出るうえ、ラスト2Fの形と合わせて終いを二重に数えていたため。
サンプルの判定結果も変わった。
配点は「成績の検証」の要素別の表を見ながら、結果がたまったら調整する前提。

点数の丸めは四捨五入（`score_round`: .5 は切り上げ、浮動小数の誤差は吸収）。
Python 標準の `round()` は偶数丸めのため、たとえば全体時計 -0.7秒（-3.5点）が -4 になり、
JS 版や意図した点数と 1 点ずれることがあったのを修正した。

### Python 版

```bash
python training_judge.py                                    # アイサンサン（data/ のサンプル）
python training_judge.py --horse ウインマーベル --workouts data/winmarvel_training.csv --races data/winmarvel_races.csv
python training_judge.py --workouts 馬_training.csv --races 馬_races.csv --pool pool.csv   # 他の馬の最終追い切りを基準に使う
python training_judge.py --json ...                         # JSON 出力（JS版との突き合わせ用）
```

アプリのメニュー「調教CSV / レースCSV / 他の馬の最終追い切りCSV を書き出し」で出したファイルをそのまま `--workouts` / `--races` / `--pool` に渡せる。

## OCR の仕組み（js/ocr.js）

1. スクショから表の白/黄色の領域を自動で切り出し、幅 1600px に拡大
2. レベル補正で背景（白・黄・グレーのセル・罫線）を白に飛ばす（二値化は Tesseract 内部）
3. Tesseract.js（英数字のみ、`0123456789./:()-`、PSM 11）で単語ごとの位置を取得
4. 日付の単語で行を検出 → 同じ行帯の数値を、全行の x 座標クラスタから推定した列に割当（右端 = 1F）
5. セル上段（累計）を採用。括弧付き・下段（ラップ）は検算と欠けた累計の補完に使う
6. コースは 5F/6F に値があればウッド、なければ坂路
7. よくある誤読を補正: `11.7`→`1.7`（先頭の1が脱落）、小数点の脱落、`10/25`→`10/125`、坂路の「-」セルのノイズ

### 精度（tests/screenshots の6枚 = PC上のスマホプレビューのキャプチャ、幅512px相当の低解像度）

| 指標 | 結果 |
|---|---|
| セル単位（日付・時刻・コース以外の 6F〜1F） | 845 / 846 = 99.9% |
| 行単位（全項目一致） | 140 / 141 |
| 誤りのうち警告で検出 | 1 / 1（警告なしの誤りは 0） |
| 複数枚を統合した結果 | 2頭分とも 60/60 行が完全一致 |
| 処理時間（PC Chrome） | 1枚 約5秒（初回はモデル読み込みで +数秒） |

iPhone の実スクショは解像度が約2.3倍あるので、これより条件は良いはず。

## 更新を公開するとき

`index.html` の `app-version`（と同じ文字列の `?v=`）と、`sw.js` の `APP_CACHE` の版番号を上げてから push する。
端末側は開いたとき・アプリに戻ったときに更新を確認し、新しい版が届くと自動で1回再読み込みする。
画面いちばん下に「版 ○○」が出るので、どの版が動いているか確認できる。

## 重賞日程の更新（年1回）

`data/graded_<年>.json` は JRA の「重賞レース一覧」から作っている。翌年の日程が出たら:

```bash
python tools/update_graded.py 2027
```

アプリは前年・今年・翌年のファイルを読み込む（無い年は無視）。

## テスト

```bash
node tests/parity.mjs        # JS版と Python版の判定一致（サンプル2頭 + ランダム300ケース）
python -m http.server 8765   # → http://localhost:8765/tests/ocr_test.html で OCR 精度テスト
```

`tests/ocr_test.html` は `tests/screenshots/` の画像を読み、`data/*.csv` の正解と照合する。
スクショは JRA-VAN の画面なのでリポジトリには含めない（`.gitignore`）。

tests/                 一致テスト・OCR テスト
